# Проверка локального комплекта

`.venv/bin/python scripts/verify_local_install.py` копирует только отслеживаемые Git файлы в отдельный временный каталог, создаёт новое виртуальное окружение и устанавливает requirements.txt. Для установки нужны доступные пакеты или локальный кеш pip. Личные базы, .env и прежнее окружение не копируются.

Скрипт применяет миграции к пустой SQLite, проверяет их согласованность, запускает весь набор тестов, создаёт вымышленный демоаккаунт, проверяет страницы кабинета и финансовый PDF. Затем запускает настоящий сервер из другого рабочего каталога, проверяет главную/CSS по HTTP и завершает собственный процесс. Временный каталог удаляется. Отчёт reports/local-install-v1.json содержит SHA исходников и версии зависимостей.

23 ноября 2026 проверка пройдена. Это воспроизведение локальной установки и сценариев; последующая визуальная проверка Chrome описана ниже. SQLite не подтверждает блокировки PostgreSQL: отдельное реальное испытание двух соединений описано в POSTGRESQL.md. Демонстрационные финансовые данные вымышлены.

## Реальный Chrome

Отдельный Python для проверки: `python3 -m venv .qa-venv`, затем `.qa-venv/bin/python -m pip install -r requirements-qa.txt`. Запуск: `.qa-venv/bin/python scripts/verify_browser.py --app-python .venv/bin/python`.

Проверка копирует отслеживаемые исходники в временный каталог, создаёт пустую SQLite, вымышленный аккаунт и демоучёт. Через настоящие формы проходят вход, создание операции с копейками и перевод между счетами. Chrome скачивает PDF и открывает основные закрытые разделы. Проверяются desktop1440 и mobile390 без горизонтального переполнения документа. Таблицы на узком экране прокручиваются внутри доступной с клавиатуры области. Шесть снимков в reports/local-visual-v1 просмотрены; устранена лишняя высота меню руководств, ранее сдвигавшая содержание за первый экран. Это проверка одного браузера, а не полный аудит доступности/совместимости. Основная установка приложения не требует Playwright.

В заключительном сценарии Chrome также проверил заполненную сегодняшнюю дату и сохранение сверки с точным остатком188750.50₽ после операции/перевода. Восемь браузерных проверок, дополнительный снимок сверки просмотрен.

Ручной ввод защищён UUID-квитанцией: повтор того же POST не дублирует деньги и аудит; конфликт данных отклоняется. Удалённая операция не восстанавливается старой формой. Квитанции — техническая таблица, не предметная. Проверены77 тестов SQLite (один PostgreSQL-сценарий пропущен); весь набор затем прошёл и на PostgreSQL16.14, см. POSTGRESQL.md.

Chrome13 сценариев включает точные суммы нового отчёта иCSV, переход к операциям без проекта, сводку всех счетов и возможные дубли из двух разных форм. Новые шесть desktop/mobile-областей просмотрены, для таблиц настроена читаемая горизонтальная прокрутка с доступом клавиатурой. Аудит2255 смешанных единиц. Новые групповые запросы отдельно наPG в этом блоке пока не проверены.
